## 1) الملخص التنفيذي

1. **الوضع الحالي مثبت بالدليل:** تقرير أعمار ذمم العملاء كان يعرض **إجمالي الفواتير الآجلة** بلا خصم قبض/مردود/شيك (جذر: `Total − PaidAmount` و`PaidAmount` يُكتب مرة واحدة عند الإنشاء). **شروط الاستعلام أُصلحت في P0-2F** (`Posted` + `asOf`) — **والمعادلة ما زالت غير مصححة** (تحتاج سياسة تخصيص).
2. **دورة الشيك مثبتة ومتسقة بالكامل مع الأستاذ** (P0-2E): تسجيل ⇒ `1102` مدين / `1200` دائن · تحصيل ⇒ `1101`/`1102` · ارتجاع ⇒ `1200`/`1102` · **الإيداع بلا قيد** · **لا حالة إلغاء** · حراس منع تكرار فعّالة · **0 قيود غير متوازنة**.
3. **دحض تجريبي:** معادلة `المتبقي + غير المخصص + تحت التحصيل = 1200` **خاطئة** (الشيك يخفّض `1200` مسبقًا) — والبديل **مشتق من القيود الفعلية** (§4).
4. **الفجوة المتبقية/الوحيدة المؤثرة:** **لا يوجد تخصيص مقبوضات للعملاء** ⇒ لا يمكن نسبة قبض إلى فاتورة ⇒ الأعمار لا تصلح كمصدر للمستحق حتى تُنفَّذ السياسة (يحتاج قرارك + Migration).
5. **هذه الوثيقة** تُحوّل الأدلة إلى **8 قرارات موصى بها**، وتميّز بوضوح بين ما هو **مثبت** وما هو **توصية** وما يحتاج **موافقتك**، وتبقى **غير معتمدة**.

## 3) معادلة المطابقة (مشتقة من القيود الفعلية — مُثبتة في P0-2E)

| الرمز | المكوّن | المصدر |
|---|---|---|
| A | رصيد `1200` ذمم العملاء (منسوب للعميل) | سطور القيود على `1200` المرتبطة بمستندات العميل |
| B | رصيد `1102` شيكات برسم التحصيل | سطور القيود المرتبطة بشيكات العميل |
| C | رصيد `1101` البنك (الحصة المتحصَّلة) | `1102 → 1101` عند `Cleared` |
| D | إجمالي الفواتير الآجلة **المرحَّلة حتى التاريخ** | `SalesInvoice` (`OnAccount`, `Posted`, `InvoiceDate <= asOf`) |
| E | المقبوضات غير المخصصة | `Σ سندات قبض مرحَّلة − Σ تخصيصات` |
| F | المبالغ المخصصة للفواتير | `CustomerPaymentAllocation` (عند تنفيذها) |
| G | مردودات مرتبطة بفاتورة (مرحَّلة) | `SalesReturn.SalesInvoiceId != null && Posted` |
| H | شيكات مقبوضة (غير مرتجعة / مرتجعة) | `BankCheck` بحالاتها الأربع |

**المطابقة المُثبتة تجريبيًا (P0-2E):**
```
A = D − G − Σ(سندات القبض) − H(غير المرتجعة) + H(المرتجعة)
A + B = D − G − Σ(سندات القبض) − H(المحصَّلة)
```
**بعد تنفيذ التخصيص (المتوقع، تحقق تجميعي إلزامي):** `Σ متبقي الفواتير + E + B = A + B + E`
**⛔ محظور:** `Σ متبقي + E + تحت التحصيل = A` — **دُحض تجريبيًا** (الشيك يخفّض `A` مسبقًا عبر `B`).
**فروق لا يغطيها النموذج [غير محسوم تقنيًا]:** قيود يدوية/افتتاحية على `1200` بلا مستند (لا تُنسب لعميل) · `F = 0` حاليًا (لا كيان تخصيص) ⇒ لا مطابقة لكل فاتورة · `PaidAmount` غير موثوق للآجل · مردودات تاريخية بلا `SalesInvoiceId` ⇒ تُعلَّم ولا تُسوَّى.

## 6) معايير القبول والاختبارات المطلوبة قبل التنفيذ
1. **تحقق تجميعي يجب أن يفشل قبل الإصلاح**: `Σ متبقي + E + B = A + B + E` (تسامح 0.005).
2. اختبارات فردية: بيع آجل بلا قبض · قبض جزئي مخصص · كامل · **غير مخصص** · قبض لعدة فواتير · عدة قبوض لفاتورة · مردود جزئي/كلي · شيك مسجَّل→محصَّل→مرتجع · تخصيص مكرر/متزامن.
3. **لا تغيير للتاريخ المحاسبي**: بصمة `COUNT/SUM` + تواريخ القيود قبل/بعد تشغيل التقارير.
4. تاريخ القطع: تخصيص بعد `asOf` لا يظهر في تقرير تاريخي.
5. انحدار: P0-2F يبقى ناجحًا + تقرير الموردين بلا تغيير.
