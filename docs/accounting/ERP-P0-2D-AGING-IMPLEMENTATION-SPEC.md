## 1) الملخص التنفيذي

1. **العيب مثبت:** تقرير أعمار ذمم العملاء يستخدم `TotalAmount − PaidAmount`، و`PaidAmount` **لا يُحدَّث بعد الإنشاء** (`SalesInvoiceService.Create.cs:170` الكاتب الوحيد) ⇒ الأعمار = **إجمالي الفواتير الآجلة** بلا خصم قبض أو مردود (`AgingReportQueries.cs:34` + `ReportServiceReportsB.cs:11,15`).
2. **⚠️ تعارض جوهري مكتشف في هذه الجولة (يحتاج قرارك):** المبدأ المبدئي **رقم 2** («الشيك تحت التحصيل ليس تحصيلًا نهائيًا») **يتعارض مع التنفيذ الحالي**: عند **تسجيل** شيك مقبوض تُرحَّل قيود **مدين `1102` (شيكات برسم التحصيل) / دائن `1200` (ذمم العملاء)** ⇒ **الذمم تُخفَّض عند التسجيل لا عند التحصيل**، والقيمة تُحمل في الحساب الوسيط `1102` حتى `Cleared` (تُحوَّل للبنك) أو `Bounced` (تعود لـ`1200`).
3. **بناءً عليه:** المعادلة `المتبقي + غير المخصص + تحت التحصيل = 1200` **غير صحيحة في هذا المشروع** (تحذيرك في محله) — المعادلة الصحيحة **§6** وهي مشتقة من القيود الفعلية.
4. **لا يوجد كيان تخصيص للعملاء** (الوحيد `PaymentAllocation` للموردين) ⇒ **تعميم النمط** لا نسخه أعمى.
5. **الهدف النهائي:** متبقٍّ محسوب لكل فاتورة + تخصيصات مخزَّنة + إبراز غير المخصص + **معادلة مطابقة قابلة للإثبات**.

## 5) قواعد التخصيص والشيكات والمردودات

| السيناريو | القاعدة |
|---|---|
| قبض واحد لعدة فواتير | عدة سجلات لنفس السند، مجموعها ≤ مبلغ السند |
| عدة قبوض لفاتورة | عدة سجلات لنفس الفاتورة، مجموعها ≤ المتبقي القابل للتحصيل |
| جزئي/كامل | مسموح؛ الكامل يُغلق الفاتورة فتختفي من الأعمار |
| تجاوز المتاح | **يُرفض** (`Allocated + Amount > Residual`) بلا أي أثر |
| FIFO | `InvoiceDate ASC, InvoiceNumber ASC, Id ASC` (**يحتاج تأكيدك**) |
| قبض غير مخصص | مسموح، يظهر منفصلًا، لا يدخل متبقي أي فاتورة |
| تعديل/إلغاء تخصيص | تعديل بحقول تدقيق؛ **لا حذف صلب** |
| عكس سند القبض | إبطال تخصيصاته (سجلات عكسية) + قيد معاكس **مرة واحدة** |
| تزامن/تكرار | قيد فريد (`ReceiptVoucherId`,`SalesInvoiceId`) للتخصيص غير المعكوس + قفل صف السند/الفاتورة + فحص الصفوف المتأثرة |
| توثيق | `AllocatedBy/At` إلزامي + `Note` عند التعديل اليدوي |
| تاريخ القطع | يعتمد **تاريخ التخصيص**؛ **يحتاج قرارك**: تاريخ التخصيص أم تاريخ السند؟ |

**مصفوفة الشيك (حالات فعلية من الكود):**
| الحالة | متبقي الفاتورة | الحساب الوسيط `1102` | `1200` | تقرير أعمار اليوم |
|---|---|---|---|---|
| `Registered` | لا تخصيص تلقائي ⇒ غير متأثر | **مدين بمقدار الشيك** | **دائن (مخفَّض)** | **لا يرى الشيك ⇒ مبالغة** |
| `Deposited` | نفسه | نفسه | نفسه | نفسه |
| `Cleared` | نفسه | يُصفَّر (للـ`1101`) | لا تغيير | لا يرى التحصيل |
| `Bounced` | نفسه | يُعكس | **يعود (مدين)** | يعود للأثر الأصلي |

**المردودات:** الربط بالفاتورة الأصلية **إلزامي** · جزئي/كلي (الكلي يُغلق) · **منع الازدواج** عند الإلغاء/الترحيل بمعرّف ارتباط واحد لكل (مردود، فاتورة).

## 6) المعادلة المحاسبية ومصفوفة المطابقة

| # | المكوّن | المصدر |
|---|---|---|
| C1 | إجمالي الفواتير الآجلة **المرحَّلة حتى تاريخ القطع** | `SalesInvoice` (`OnAccount`, `Posted`, `InvoiceDate <= asOf`) |
| C2 | مردودات المبيعات **المرتبطة بفاتورة** حتى التاريخ | `SalesReturn` (`SalesInvoiceId != null`) |
| C3 | سندات القبض **المرحَّلة** حتى التاريخ | `ReceiptVoucher` (`Posted`, `VoucherDate <= asOf`) |
| C4 | شيكات مقبوضة (مسجَّلة/مودعة/محصَّلة/مرتجعة) | `BankCheck` |
| C5 | تخصيصات مخزَّنة (عند تنفيذها) | `CustomerPaymentAllocation` |
| C6 | رصيد `1200` المنسوب للعميل | سطور القيود المرتبطة بمستنداته |
| C7 | رصيد `1102` (شيكات برسم التحصيل) | سطور القيود المرتبطة بشيكاته |

**المطابقة القابلة للإثبات (V3 = الأستاذ):**
```
الذمم الدفترية للعميل = C1 − C2 − C3 − (C4 غير المرتجعة) + (C4 المرتجعة)
```
**مصفوفة العرض بعد الإصلاح:**
```
متبقي كل فاتورة      = إجمالي الفاتورة − مردوداتها − تخصيصاتها
إجمالي الذمم (V1')   = Σ متبقي الفواتير حتى تاريخ القطع
غير المخصص           = C3 + C4المسجَّلة − Σ C5     ← بند منفصل لا يدخل V1'
تحت التحصيل (`1102`) = C4 المسجَّلة/المودعة (لا المرتجعة)
```
**⛔ قاعدة محظورة صراحةً:** لا يُستخدم `المتبقي + غير المخصص + تحت التحصيل = 1200` — لأن الشيك يخفّض `1200` مسبقًا عبر `1102`، فأي صيغة تُضيف «تحت التحصيل» إلى طرف `1200` **تُضاعف الأثر**.
**⚠️ المعادلة النهائية تحتاج إثباتًا تجريبيًا** (اختبار مطابقة على بيانات اصطناعية يقارن كل مكوّن) — **لم يُنفَّذ في هذه المهمة**.

## 8) خطة Migration والتراجع (تصميم فقط — لا تنفيذ)

1. **قبل:** Backup كامل (قاعدة + بصمات ملفات) + خط أساس موثَّق (C1..C7 لكل عميل) + بصمة SHA للنتيجة.
2. **Migration:** إنشاء جدول `CustomerPaymentAllocations` **فقط** — **لا تعبئة تخمينية**.
3. **التعبئة:** **لا تُعبَّأ تخصيصات تاريخية**؛ الفواتير القديمة تبقى بلا تخصيصات، ويُظهر التقرير الجديد متبقيًا محسوبًا + **«غير مخصص» صريحًا** (لا إخفاء للفروق).
4. **التحقق (بوابة إيقاف):** إن لم يتحقق `Σ V1' + غير المخصص + تحت التحصيل = رصيد 1200 + F(شيكات)` عند حد تسامح مُعلن ⇒ **إيقاف وعدم المتابعة**.
5. **التراجع:** إسقاط الجدول + استعادة النسخة؛ التغييرات في حساب التقارير تُتراجع بنشر النسخة السابقة (**لا تغيير على القيود إطلاقًا**).
6. **إثبات عدم تغيير القيود:** بصمة `COUNT/SUM` على `JournalEntries`/`JournalEntryLines` + أعلى `CreatedAt` قبل/بعد — **يجب أن تتطابق**.
7. **غير القابل لإعادة البناء:** عملاء بقيود افتتاحية/يدوية أو مردودات بلا رابط ⇒ **يُعلَّم** «فرق غير قابل للإثبات» ولا يُسوَّى.
